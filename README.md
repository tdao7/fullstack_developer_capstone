# IBM Car Dealership Reviews Capstone Project

**Repository:** `ibm-dealership-capstone` (proposed public repository under GitHub account `tdao7`)  
**Project:** Best Cars — Django / React Car Dealership Review Application

An educational, functional local demonstration for the IBM Full Stack Application Development Capstone. It includes Django authentication, user registration, state-filtered dealer discovery (including Kansas), review creation, car make/model records, sentiment analysis, and an optional React registration component.

> **Evidence and honesty:** Images and terminal transcripts are generated by scripts that interact with a running server. They are not pre-fabricated. GitHub Actions or public deployment results must come from real completed runs. All dealers, staff, addresses and reviews are fictional training data. Database uses SQLite for the local demonstration; use a durable cloud database for production.

## Start on macOS/Linux

On Macs with the built-in Python 3.9, Django 5.1+ cannot be installed. Install Python 3.12 and let setup select it:

```bash
brew install python@3.12
CAPSTONE_PYTHON="$(brew --prefix python@3.12)/bin/python3.12" bash setup_local.sh
cd server && source .venv/bin/activate && python manage.py runserver 127.0.0.1:8000
```

Open http://127.0.0.1:8000/ and http://127.0.0.1:8000/admin/.

For local course demonstration only, `setup_local.sh` creates `capstone_demo / CapstoneDemo2026!` and `root / CourseAdmin2026!`. Override with `CAPSTONE_DEMO_PASSWORD` and `CAPSTONE_ADMIN_PASSWORD` environment variables. Never reuse or deploy demonstration passwords. In production, set `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS` and `DJANGO_DEBUG=0`.

## Deployment

`Dockerfile` and `render.yaml` are deployment starting points. Deploy with a cloud provider you control and use a persisted database for review durability. Set `DEPLOYMENT_URL=https://YOUR_REAL_HOST` and run:

```bash
bash collect_deployment_url.sh
python capture_screenshots.py --base-url http://127.0.0.1:8000 --deployment-url "$DEPLOYMENT_URL"
```

**Do not submit** CI logs or deployed screenshots unless the action or deployment actually succeeded.

## Main endpoints

| Endpoint | Description |
|---|---|
| `GET /djangoapp/get_dealers` | All dealers |
| `GET /djangoapp/get_dealers/Kansas` | Dealers in Kansas |
| `GET /djangoapp/dealer/1` | Detail for a dealer |
| `GET /djangoapp/reviews/dealer/1` | Reviews for a dealer |
| `GET /djangoapp/get_cars` | Car makes and models |
| `POST /djangoapp/register` | Register |
| `POST /djangoapp/login` | Log in and get session cookie |
| `GET /djangoapp/logout` | Log out |
| `POST /djangoapp/add_review` | Add a review (requires login) |
| `GET /djangoapp/analyze/Fantastic%20services` | Basic sentiment |
| `GET http://127.0.0.1:5050/analyze/Fantastic%20services` | Independent sentiment microservice |

The API returns JSON to cURL and to JavaScript (`Accept: application/json`). For selected read endpoints, a browser requesting `text/html` shows the corresponding frontend page at that same endpoint URL.
